# CRM-3 Support Tickets and Activities Data Dictionary

**Contract:** CRM-3 V1, issue #26 (CRM3-01; approved implementation source of truth).
Domain at issue: Ticket fields subject, status, priority, contact link, optional order_ref text and note. Status values: `New`, `Open`, `Waiting`, `Solved`, `Closed`; Priority values: `Low`, `Normal`, `High`, `Urgent`. Notes retain author and created_at; ordered newest-first. In V1 `order_ref` is text, not an enforced ERP foreign key. No timeline/SLA in V1.

All timestamps are PostgreSQL `timestamptz` in UTC. UUIDs are generated by PostgreSQL (`gen_random_uuid()`). The owner for every object below is the CRM-3 module; cross-module relationships access data through owning APIs or approved read-only projections, never by direct cross-schema foreign keys or mutations.

## `crm3.crm3_tickets`

| Field | PostgreSQL type | Nullability | Meaning | Owner | Constraints |
|---|---|---|---|---|---|
| `id` | `uuid` | NOT NULL | Support ticket primary key. | CRM-3 | Primary key; generated by `gen_random_uuid()`. |
| `subject` | `text` | NOT NULL | Brief summary or title of the ticket. | CRM-3 | Must contain at least one non-whitespace character. |
| `status` | `text` | NOT NULL | Ticket resolution state. | CRM-3 | Must be one of `New`, `Open`, `Waiting`, `Solved`, `Closed`. Default `New`. |
| `priority` | `text` | NOT NULL | Ticket priority level. | CRM-3 | Must be one of `Low`, `Normal`, `High`, `Urgent`. Default `Normal`. |
| `contact_id` | `uuid` | NOT NULL | Identifier of the customer contact who opened/is linked to the ticket. | CRM-3 | Logical link to CRM-1 contact; no cross-schema FK constraint. |
| `order_ref` | `text` | NULL | Optional commercial order reference number. | CRM-3 | Plain text identifier in V1; not a hard foreign key to ERP. |
| `source_system` | `text` | NULL | Origin system for imported tickets. | CRM-3 | Present together with `source_id`; `(source_system, source_id)` is unique. |
| `source_id` | `text` | NULL | Stable identifier in the origin system. | CRM-3 | Present together with `source_system`; `(source_system, source_id)` is unique. |
| `created_at` | `timestamptz` | NOT NULL | Ticket creation timestamp. | CRM-3 | Defaults to `now()`. Indexed descending. |
| `updated_at` | `timestamptz` | NOT NULL | Last modification timestamp. | CRM-3 | Defaults to `now()`. |

Indexes:
- `crm3_tickets_source_key`: Unique `(source_system, source_id)`.
- `crm3_tickets_contact_id_idx`: B-tree index on `contact_id`.
- `crm3_tickets_status_idx`: B-tree index on `status`.
- `crm3_tickets_priority_idx`: B-tree index on `priority`.
- `crm3_tickets_created_at_idx`: B-tree index on `created_at DESC`.

## `crm3.crm3_notes`

| Field | PostgreSQL type | Nullability | Meaning | Owner | Constraints |
|---|---|---|---|---|---|
| `id` | `uuid` | NOT NULL | Note primary key. | CRM-3 | Primary key; generated by `gen_random_uuid()`. |
| `ticket_id` | `uuid` | NOT NULL | Foreign key referencing the parent ticket. | CRM-3 | Foreign key to `crm3.crm3_tickets(id)` with `ON DELETE CASCADE`. |
| `author_id` | `text` | NOT NULL | Identifier of the note author (user or system agent). | CRM-3 | Must contain at least one non-whitespace character. Populated from authenticated server context. |
| `note_text` | `text` | NOT NULL | Append-only note content. | CRM-3 | Must contain at least one non-whitespace character. |
| `created_at` | `timestamptz` | NOT NULL | Creation timestamp. | CRM-3 | Defaults to `now()`. Deterministic tie-breaker for newest-first sorting. |

Indexes:
- `crm3_notes_ticket_id_idx`: B-tree index on `ticket_id`.
- `crm3_notes_ticket_created_at_idx`: Composite index on `(ticket_id, created_at DESC)`.

## 3. Public REST API Specification & Bounded Pagination (`/api/v1/crm-tickets`)

| Method | Endpoint | Description | Request Body | Response | Error Codes |
|---|---|---|---|---|---|
| `GET` | `/api/v1/crm-tickets/tickets` | List tickets with filters (`status`, `priority`, `contactId`, `search`), bounded pagination (`page`, `pageSize` <= 100). | None | `CRM3TicketListResponse` | 400 (INVALID_QUERY), 401, 403 |
| `GET` | `/api/v1/crm-tickets/tickets/{id}` | Read single ticket by UUID with enriched contact metadata. | None | `CRM3TicketRead` | 400 (VALIDATION_ERROR), 401, 403, 404 (NOT_FOUND) |
| `POST` | `/api/v1/crm-tickets/tickets` | Create support ticket with contact existence verification and optional initial note. | `CRM3TicketCreate` | `CRM3TicketRead` (201) | 400 (VALIDATION_ERROR), 401, 403, 422 (Unprocessable) |
| `PATCH` | `/api/v1/crm-tickets/tickets/{id}` | Update ticket fields (status, priority, subject, contactId, orderRef). | `CRM3TicketPatch` | `CRM3TicketRead` | 400 (VALIDATION_ERROR), 401, 403, 404 (NOT_FOUND), 422 |
| `GET` | `/api/v1/crm-tickets/tickets/{id}/notes` | List ticket notes ordered newest-first with timestamp/id tie-breaker. | None | `CRM3NoteListResponse` | 400 (INVALID_QUERY), 401, 403, 404 (NOT_FOUND) |
| `POST` | `/api/v1/crm-tickets/notes` | Append a note to a ticket (append-only audit trail). | `CRM3NoteCreate` | `CRM3Note` (201) | 400 (VALIDATION_ERROR), 401, 403, 404 (NOT_FOUND) |

### Query & Pagination Bounds
- `page`: 1-based positive integer (default 1).
- `pageSize`: 1-based positive integer bounded by hard cap of 100 (default 25). Requests with `pageSize > 100` are rejected with `400 Bad Request` (`INVALID_QUERY`).
- Deterministic Ordering: Tickets ordered `createdAt DESC, id DESC`. Notes ordered `createdAt DESC, id DESC`.
- Search: Server-side case-insensitive match on `subject` and `orderRef`.
- Domain Invariants: Status restricted to `[New, Open, Waiting, Solved, Closed]`; Priority restricted to `[Low, Normal, High, Urgent]`.

## 4. Frontend Module Routes, Navigation & Layout Shell (CRM3-16)

### Module Route Registration
CRM-3 registers 5 primary sub-views under the common ClearShift layout shell:

| Route Path | View Identifier | Display Title | Nav Label | Required Capability |
| :--- | :--- | :--- | :--- | :--- |
| `/crm-3/tickets` | `crm3-tickets` | Support Tickets Queue | Tickets | `module.read` |
| `/crm-3/activities` | `crm3-activities` | Customer Activity Timeline | Activities | `module.read` |
| `/crm-3/notes` | `crm3-notes` | Internal Ticket Notes | Notes | `module.read` |
| `/crm-3/sla` | `crm3-sla` | SLA Tracking & Priority Escalations | SLA Tracking | `module.read` |
| `/crm-3/imports` | `crm3-imports` | Import Batches & Receipts | Imports | `module.read` |

### Hub Authentication & Route Guards
* **Session Verification:** Route guards verify the user's active Hub session before allowing access to any module route.
* **Unauthenticated Access:** Unauthenticated requests or expired sessions are intercepted and redirected to `/login?returnUrl=<encoded_path>`.
* **RBAC Authorization:** All module routes require the `module.read` capability. Users lacking this capability are redirected to `/access-denied?required=module.read`.

### Layout Shell & Accessibility Standards
* **ARIA Landmarks:** Employs `<header role="banner">`, `<nav aria-label="Breadcrumb">`, `<nav role="tablist">`, and `<main id="main-content" role="main">` with `<section role="tabpanel">`.
* **Skip Link:** Provides `<a href="#main-content" class="cs-skip-link">Skip to main content</a>` for keyboard accessibility.
* **Keyboard Navigation:** Tab controls support `ArrowLeft`, `ArrowRight` (with cyclic wrap-around), `Home`, and `End` navigation for full keyboard-driven operation.
* **Title Synchronization:** Dynamically sets `document.title` to `ClearShift | CRM-3 - <View Title>`.

## 8. Search, Faceted Filters, and Active Filter Tags (CRM3-18)

Conforms to Gate G2 requirements for Issue #151 ([CRM3-18]). Provides server-side debounced search, faceted filter dimensions, active pill tags, and bidirectional URL parameter synchronization.

### Debounced Search Input Protocol
- **Debounce Threshold**: Fixed at `300ms` (`SEARCH_DEBOUNCE_MS = 300`).
- **Immediate Execution**: Pressing `Enter` or calling `flushSearch()` bypasses timer delay and executes search immediately.
- **Immediate Cancellation / Reset**: Pressing `Escape` or activating the `×` button flushes or clears search term immediately.
- **Server Match Targets**: Case-insensitive match on `subject` and `orderRef`.

### Standard Faceted Filter Dimensions
- **`status` Facet**: All Statuses, `New`, `Open`, `Waiting`, `Solved`, `Closed`.
- **`priority` Facet**: All Priorities, `Low`, `Normal`, `High`, `Urgent`.

### Active Filter Pills & State Reset
- Active search and facet selections generate removable filter pills (`ActiveFilterPill`).
- Filter pills can be cleared individually via `removeFilter(key)`.
- Global `clearAll()` / "Clear All" action clears search and resets all faceted selections simultaneously.
- When search or filter modifications occur, table pagination automatically resets to `page = 1` to prevent phantom page errors.
- Empty states under active filter conditions render `cs-empty-filter-state` with "Reset All Filters" CTA.
