# CRM-1 Data Dictionary

**Contract:** CRM-1 V1, issue #6 (issue fields were approved as the implementation source of truth for this change). The checked-in master architecture spec does not define the columns for `crm1_leads` and assigns consent ownership to CRM-4; this dictionary records the approved CRM-1 representation and does not create cross-schema foreign keys or write paths.

All timestamps are PostgreSQL `timestamptz` in UTC. UUIDs are generated by PostgreSQL unless supplied by an internal caller. The owner for every object below is the CRM-1 module; the Migration Kit accesses target writes through the CRM-1 adapter/API, never by writing these tables directly.

## Import entities

`crm1.crm1_import_batches` persists batch state and counts. `crm1.crm1_import_receipts` is written atomically with successful target rows by the CRM-1 adapter and makes imports idempotent. `crm1.crm1_import_rejects` records rejected row references and reasons. The API-facing views `crm1.crm1_import_summary` and `crm1.crm1_reject_view` expose only the batch summary and reject fields; neither exposes raw input rows.

| Table / field | PostgreSQL type | Nullability | Meaning | Owner | Constraints |
|---|---|---|---|---|---|
| `crm1_import_batches.id` | `uuid` | NOT NULL | Import batch identifier. | CRM-1 | Primary key; generated by PostgreSQL. |
| `crm1_import_batches.source_system` | `text` | NOT NULL | Source system name. | CRM-1 | Non-whitespace. |
| `crm1_import_batches.status` | `text` | NOT NULL | `pending`, `processing`, `completed`, or `failed`. | CRM-1 | Defaults to `pending`; check constraint. |
| `crm1_import_batches.idempotency_key` | `text` | NULL | Caller-supplied key identifying an import request. | CRM-1 | Unique when present; paired with `request_hash`. |
| `crm1_import_batches.request_hash` | `text` | NULL | SHA-256 digest of the validated request payload. | CRM-1 | Paired with `idempotency_key`; mismatched key reuse returns 409. |
| `crm1_import_batches.loaded_count` | `integer` | NOT NULL | Number of accepted rows. | CRM-1 | Defaults to 0; non-negative check. |
| `crm1_import_batches.rejected_count` | `integer` | NOT NULL | Number of rejected rows. | CRM-1 | Defaults to 0; non-negative check. |
| `crm1_import_batches.created_at` | `timestamptz` | NOT NULL | Batch creation time. | CRM-1 | Defaults to `now()`. |
| `crm1_import_batches.updated_at` | `timestamptz` | NOT NULL | Last state/count update. | CRM-1 | Defaults to `now()`. |

| `crm1_import_receipts.id` | `uuid` | NOT NULL | Receipt primary key. | CRM-1 | Primary key; generated by PostgreSQL. |
| `crm1_import_receipts.batch_id` | `uuid` | NOT NULL | Owning import batch. | CRM-1 | Foreign key to batches; cascade on batch deletion. |
| `crm1_import_receipts.source_row` | `integer` | NOT NULL | 1-based source row number. | CRM-1 | Must be positive; unique with batch and entity. |
| `crm1_import_receipts.entity` | `text` | NOT NULL | `contact`, `company`, or `lead`. | CRM-1 | Check constraint. |
| `crm1_import_receipts.source_system` | `text` | NOT NULL | Origin system. | CRM-1 | Non-whitespace. |
| `crm1_import_receipts.source_id` | `text` | NOT NULL | Origin record identifier. | CRM-1 | Non-whitespace. |
| `crm1_import_receipts.target_id` | `uuid` | NOT NULL | ID of the created target record. | CRM-1 | No cross-module foreign key. |
| `crm1_import_receipts.idempotency_key` | `text` | NOT NULL | Stable import-row idempotency key. | CRM-1 | Non-whitespace and unique. |
| `crm1_import_receipts.created_at` | `timestamptz` | NOT NULL | Receipt creation time. | CRM-1 | Defaults to `now()`. |
| `crm1_import_rejects.id` | `uuid` | NOT NULL | Reject primary key. | CRM-1 | Primary key; generated by PostgreSQL. |
| `crm1_import_rejects.batch_id` | `uuid` | NOT NULL | Owning import batch. | CRM-1 | Foreign key to batches; cascade on batch deletion. |
| `crm1_import_rejects.source_row` | `integer` | NOT NULL | 1-based rejected row number. | CRM-1 | Must be positive. |
| `crm1_import_rejects.entity` | `text` | NOT NULL | `contact`, `company`, or `lead`. | CRM-1 | Check constraint. |
| `crm1_import_rejects.reason_code` | `text` | NOT NULL | Stable rejection reason identifier. | CRM-1 | Non-whitespace. |
| `crm1_import_rejects.message` | `text` | NOT NULL | Safe, non-raw rejection message. | CRM-1 | Non-whitespace; do not include raw PII. |
| `crm1_import_rejects.created_at` | `timestamptz` | NOT NULL | Reject creation time. | CRM-1 | Defaults to `now()`. |

Both import views are SQL views over CRM-1-owned tables. The rejects view intentionally excludes the imported row payload.

The public import request requires `batchId`, an `Idempotency-Key` header, and rows with positive `sourceRow` values. A retry with the same key and payload returns the original batch and receipts; reusing a key with a different payload returns 409. Every successful target mutation and its per-row receipt commit together. User CRUD cannot set source identity, Golden ID, consent, or unsubscribe fields. Import rows cannot set consent or unsubscribe state, and an existing source-system/source-id match is never overwritten.

## Index and API behavior

- Contact search is case-insensitive over first name, last name, and email and must be executed in PostgreSQL with `LIMIT`/`OFFSET`; `pageSize` defaults to 25 and `page` to 1.
- The public source/id pair is unique for companies, contacts, and leads, making re-imports idempotent.
- Consent and unsubscribe timestamps are compared in PostgreSQL before state changes. A stale or equal event that changes state is rejected with check-violation SQLSTATE `23514`.
- Cross-module references remain API/projection concerns. CRM-1 declares no FK to another module's schema.

## Clean local migration / demo

Use a disposable PostgreSQL 18.6 database and synthetic data only:

```sh
DATABASE_URL=postgres://localhost:5432/clearshift_dev npm run db:migrate
DATABASE_URL=postgres://localhost:5432/clearshift_dev npm run db:migrate
```

The first run applies `crm1_v1`; the second reports it skipped from `public.schema_migrations`. For PostgreSQL constraint tests, apply the same migration to an isolated test database, then run:

```sh
DATABASE_URL_TEST=postgres://localhost:5432/clearshift_test npm run db:migrate:test
DATABASE_URL_TEST=postgres://localhost:5432/clearshift_test npm test -- apps/crm/modules/crm-1/tests/db/schema.test.ts
```

## Public API Endpoints (`/api/v1/crm-contacts`)

* `GET /health`: Health check and version verification.
* `GET /contacts`: Server-paged contacts list; case-insensitive search matches first name, last name, or email. `pageSize` defaults to 25; results are ordered by last name and first name.
* `GET /contacts/:id`: Retrieve contact by UUID.
* `POST /contacts`: Create contact; an optional company link and lead status are validated.
* `PATCH /contacts/:id`: Partially update editable contact fields; source identity, Golden ID, consent, and unsubscribe fields are server-maintained.
* `GET /companies`: Server-paged companies list; search matches name, email, or tax number. `pageSize` defaults to 25.
* `GET /companies/:id`: Retrieve company by UUID.
* `POST /companies`: Create company.
* `PATCH /companies/:id`: Update editable company fields; source identity is server-maintained.
* `GET /leads`: Server-paged leads list; search matches the linked contact's name or email. `pageSize` defaults to 25.
* `GET /leads/:id`: Retrieve lead by UUID.
* `POST /leads`: Create lead.
* `PATCH /leads/:id`: Update a lead or transition its status.
* `POST /imports`: Process a batch with required `batchId`, positive per-row `sourceRow`, and `Idempotency-Key`; same-key retries return the original result.
* `GET /imports/:batch`: Check batch execution status.
* `GET /imports/:batch/rejects`: Retrieve paginated rejected rows for review.
