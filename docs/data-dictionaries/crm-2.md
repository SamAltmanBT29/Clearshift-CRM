# CRM-2 Deals, Pipeline and Quotes — Data Dictionary & Functional Specification

**Scope:** V1 / Issues #16, #19 ([CRM2-04]), #20 ([CRM2-05]), #21 ([CRM2-06]). Owner: Group 2 — Role 3 (Frontend / Review-screen Engineer) & CRM-2 Team. All tables live in PostgreSQL 18.6 schema `crm2`. UUIDs are generated by PostgreSQL. Timestamps use `timestamptz` and default to `now()`.

---

## 1. Relational Tables

### 1.1 `crm2.crm2_stages`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Stable stage identifier | Primary key |
| `name` | TEXT | NOT NULL | Fixed stage label | One of `New`, `Qualified`, `Proposal`, `Negotiation`, `Won`, `Lost`; unique |
| `position` | SMALLINT | NOT NULL | Display order from 1 to 6 | Unique; range 1–6 |
| `is_won` | BOOLEAN | NOT NULL | Whether this is the successful terminal stage | True only for `Won` |

**Rules:** Migration seeds the six approved stages with stable IDs. The database rejects stage updates and deletes. The API exposes stages as read-only; stage insertion is reserved for controlled migrations.

### 1.2 `crm2.crm2_deals`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Deal identifier | Primary key |
| `name` | TEXT | NOT NULL | Deal name | Must not be blank (max 255 chars) |
| `contact_id` | UUID | NULL | Contact reference from CRM-1 | No cross-schema FK; nullable so orphan deals can be shown and warned about |
| `value` | NUMERIC(14,2) | NOT NULL | Opportunity monetary value | Non-negative decimal; never floating point |
| `currency` | TEXT | NOT NULL | Currency code | Exactly 3 uppercase letters (ISO 4217, e.g. USD, EUR, GBP) |
| `stage_id` | UUID | NOT NULL | Current sales stage | FK to `crm2.crm2_stages.id`; deletion restricted |
| `close_date` | DATE | NULL | Expected or actual close date | Required in V1 forms (YYYY-MM-DD) |
| `source_system` | TEXT | NULL | Origin system for imported deal | Paired with source_id; pair unique |
| `source_id` | TEXT | NULL | Stable identifier in origin system | Paired with source_system; pair unique |
| `created_at` | TIMESTAMPTZ | NOT NULL | Creation audit timestamp | Defaults to now(); read-only |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Last update audit timestamp | Defaults to now(); writers refresh on update; read-only |

Indexes support case-insensitive name search, contact lookup, stage filtering and close-date lookup. Contact existence is checked through CRM-1's public reference resolver, not a cross-schema foreign key.

### 1.3 `crm2.crm2_quotes`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Quote identifier | Primary key |
| `quote_number` | TEXT | NOT NULL | Human-readable quote number | Non-blank and unique across all quotes (e.g. Q-2026-001) |
| `deal_id` | UUID | NOT NULL | Parent deal | FK to `crm2.crm2_deals.id`; deletion restricted |
| `quote_date` | DATE | NOT NULL | Date the quote was issued | Required (YYYY-MM-DD) |
| `amount` | NUMERIC(14,2) | NOT NULL | Quote amount | Non-negative decimal |
| `currency` | TEXT | NOT NULL | Currency code | Explicit 3-letter ISO code (matches deal) |
| `note` | TEXT | NULL | Commercial terms / scope note | Optional text |
| `source_system` | TEXT | NULL | Origin system for imported quote | Paired with source_id; pair unique |
| `source_id` | TEXT | NULL | Stable identifier in origin system | Paired with source_system; pair unique |
| `created_at` | TIMESTAMPTZ | NOT NULL | Creation timestamp | Defaults to now(); read-only |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Last update timestamp | Defaults to now(); writers refresh on update; read-only |

Indexes support deal and quote-date lookups.

## 3. Deal Stage Transitions & Pipeline State Machine (CRM2-06)

The sales pipeline follows a strict directed transition graph:
- **Forward Progression**: `New` -> `Qualified` -> `Proposal` -> `Negotiation` -> `Won`
- **Loss Progression**: Any active stage (`New`, `Qualified`, `Proposal`, `Negotiation`) can transition directly to `Lost`.
- **Idempotency**: Same-stage updates (`current === next`) are permitted.
- **Terminal Stages**:
  - `Won` (`is_won = true`): Closed-Won terminal state. Outgoing transitions: `[]`
  - `Lost` (`is_won = false`): Closed-Lost terminal state. Outgoing transitions: `[]`
- **Forbidden Transitions**: Backward transitions (e.g. `Qualified` -> `New`), skip transitions (e.g. `New` -> `Won`), or transitions originating from terminal stages (`Won` or `Lost`) are strictly rejected before commit with HTTP 422 Unprocessable Entity (`INVALID_DEAL_STAGE_TRANSITION`).

### Transition Matrix

| Current Stage | Allowed Next Stages | Terminal? | Rejection Code on Illegal Transition |
|---|---|---|---|
| `New` | `Qualified`, `Lost` | No | `INVALID_DEAL_STAGE_TRANSITION` (422) |
| `Qualified` | `Proposal`, `Lost` | No | `INVALID_DEAL_STAGE_TRANSITION` (422) |
| `Proposal` | `Negotiation`, `Lost` | No | `INVALID_DEAL_STAGE_TRANSITION` (422) |
| `Negotiation` | `Won`, `Lost` | No | `INVALID_DEAL_STAGE_TRANSITION` (422) |
| `Won` | `[]` | Yes | `INVALID_DEAL_STAGE_TRANSITION` (422) |
| `Lost` | `[]` | Yes | `INVALID_DEAL_STAGE_TRANSITION` (422) |

## 4. Referential Integrity & Validation Rules

1. **CRM-1 Contact Link (`contact_id`)**:
   - Optional / nullable.
   - When null or undefined: Represents an orphan deal. The read API returns `is_orphan: true`, and the UI renders a visible warning badge. An orphan deal is never silently dropped or hidden.
   - When provided (UUID): Resolved via CRM-1's public `ReferenceResolver` or API (`/api/v1/crm-contacts/contacts/{id}`). If the contact ID does not exist, the write operation is aborted before mutation with HTTP 422 Unprocessable Entity (`REFERENCE_NOT_FOUND`, field: `contact_id`).
   - No direct SQL foreign keys or cross-schema writes to `crm1` tables are permitted.
2. **Deal Reference on Quotes (`deal_id`)**:
   - Mandatory foreign key to `crm2.crm2_deals.id`.
   - Verified before commit. Non-existent deal references fail with HTTP 422 Unprocessable Entity (`REFERENCE_NOT_FOUND`, field: `deal_id`).
3. **Quote Number Uniqueness (`quote_number`)**:
   - Unique human-readable quote identifier.
   - Duplicate quote numbers are rejected with HTTP 409 Conflict (`DUPLICATE_RECORD`, field: `quote_number`).

## 5. Read-Model Consistency

- All read operations (`GET /deals`, `GET /deals/{id}`, `GET /quotes`, `GET /quotes/{id}`) read from authoritative state.
- Derived values (`is_orphan`, `stage_name`, `quotesCount`, `totalQuotesAmount`) are computed deterministically.
- Mutations return updated projections immediately with zero stale cache lags.

## 6. UI Screens Catalog & Navigation Architecture (CRM2-05)

Every V1 screen is fully integrated and preserves list context navigation:

1. **`DealsListPage` (`/crm-2/deals`)**:
   - Table of sales deals with server-side pagination, search by name/contact, and stage filtering.
   - Distinct badges for pipeline stages and visible warning pill for orphan deals (`is_orphan = true`).
   - Actions: `+ New Deal` (navigates to create form), `View` (navigates to detail view), `Quotes` (opens deal detail quotes).

2. **`DealDetailPage` (`/crm-2/deals/:id`)**:
   - Comprehensive detail view displaying all opportunity attributes.
   - Header with stage pill, orphan badge, and action buttons (`Edit Deal`, `Refresh`, `← Back to Deals`).
   - Overview cards: Value & Stage, Contact Reference (prominent warning for orphan deals), Audit Metadata (read-only IDs and timestamps).
   - Linked Quotes Sub-Table: Lists all quotes attached to this deal, displays server-computed total quote amount, and provides `+ Add Quote` button.

3. **`DealFormPage` (`/crm-2/deals/new` and `/crm-2/deals/:id/edit`)**:
   - Create or edit deal opportunity using `DealForm`.
   - Field-level validation according to OpenAPI contract.
   - Visual orphan deal notice when contact ID is omitted.
   - Read-only system metadata panel when in edit mode.
   - Discard confirmation modal if dirty changes exist.
   - Preserves user input values without loss on server validation errors.

4. **`QuoteFormPage` (`/crm-2/quotes/new` and `/crm-2/quotes/:id/edit`)**:
   - Create or edit commercial quote linked to parent deal using `QuoteForm`.
   - Read-only deal context (parent deal name and UUID).
   - Validates quote number uniqueness, issuance date, decimal amount, and currency.
   - Cancel confirmation if form is dirty.

## 7. Field Contracts, Helper Text, and Authoritative Validation

| Entity | Field | Form Label | Helper Text | Validation / Error Message |
|---|---|---|---|---|
| **Deal** | `name` | Deal Name | Enter a descriptive title for this sales opportunity. | Required. Non-empty string (1–255 chars). Error: `Deal name is required` |
| **Deal** | `contact_id` | Contact UUID | Optional link to CRM-1 contact. Leave blank for an Orphan Deal. | Nullable UUID. When null, UI visibly warns: `Orphan Deal: No contact is linked.` |
| **Deal** | `value` | Deal Value | Non-negative decimal monetary amount (e.g. 50000.00). | Non-negative decimal string (`^\d+(\.\d{1,4})?$`). Error: `Value must be a valid non-negative decimal string` |
| **Deal** | `currency` | Currency | Explicit 3-letter uppercase ISO 4217 currency code. | Regex `^[A-Z]{3}$`. Error: `Currency must be an explicit 3-letter uppercase ISO code (e.g. USD, EUR, GBP)` |
| **Deal** | `stage_name` | Pipeline Stage | Fixed V1 pipeline stage progression. | Exactly one of: `New`, `Qualified`, `Proposal`, `Negotiation`, `Won`, `Lost`. |
| **Deal** | `close_date` | Target Close Date | Projected or actual closing date in YYYY-MM-DD format. | Regex `^\d{4}-\d{2}-\d{2}$`. Error: `Close date must be in YYYY-MM-DD format` |
| **Quote** | `quote_number` | Quote Number | Unique quote reference code (e.g. Q-2026-001). | Required, unique string. Error: `Quote number is required` / `Domain Invariant Violation: Quote number must be unique.` |
| **Quote** | `deal_id` | Linked Deal | Parent sales deal to which this quote belongs. | Valid Deal UUID. Read-only in form. |
| **Quote** | `date` | Quote Date | Issuance date in YYYY-MM-DD format. | Regex `^\d{4}-\d{2}-\d{2}$`. Error: `Quote date must be in YYYY-MM-DD format` |
| **Quote** | `amount` | Quote Amount | Non-negative decimal quote total amount. | Non-negative decimal string. Error: `Amount must be a valid non-negative decimal string` |
| **Quote** | `currency` | Currency | Explicit 3-letter uppercase ISO code. | Exactly 3 uppercase letters (e.g. USD). |
| **Quote** | `note` | Scope / Terms Note | Optional notes, deliverables summary, or commercial terms. | Optional string. |
