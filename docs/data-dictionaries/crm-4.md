# CRM-4 Marketing Lists & Campaign History — Data Dictionary & Functional Specification

**Scope:** V1 / Issues #169 ([CRM4-16]), #173 ([CRM4-20]), #174 ([CRM4-21]). Owner: Group 4 — Role 3 (Frontend / Review-screen Engineer) & CRM-4 Team. All tables live in PostgreSQL 18.6 schema `crm4`. UUIDs are generated by PostgreSQL. Timestamps use `timestamptz` and default to `now()`.

---

## 1. Relational Tables

### 1.1 `crm4.crm4_lists`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Stable marketing list identifier | Primary key |
| `name` | TEXT | NOT NULL | Marketing list name | Non-blank string (max 255 chars) |
| `description` | TEXT | NULL | Human-readable list purpose/description | Optional text |
| `campaign_count` | INTEGER | NOT NULL | Computed count of associated campaigns | Defaults to 0; non-negative |
| `member_count` | INTEGER | NOT NULL | Computed count of active/historic members | Defaults to 0; non-negative |
| `created_at` | TIMESTAMPTZ | NOT NULL | Creation audit timestamp | Defaults to now(); read-only |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Last update audit timestamp | Defaults to now(); writers refresh on update; read-only |

### 1.2 `crm4.crm4_campaigns`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Campaign identifier | Primary key |
| `name` | TEXT | NOT NULL | Campaign name | Non-blank string (max 255 chars) |
| `campaign_date` | DATE | NOT NULL | Recorded execution or reference date | Format `YYYY-MM-DD` |
| `list_id` | UUID | NOT NULL | Linked marketing list | FK to `crm4.crm4_lists.id`; **IMMUTABLE after creation** |
| `member_count` | INTEGER | NOT NULL | Count of recorded campaign participants | Defaults to 0; non-negative |
| `created_at` | TIMESTAMPTZ | NOT NULL | Creation audit timestamp | Defaults to now(); read-only |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Last update audit timestamp | Defaults to now(); writers refresh on update; read-only |

**Domain Invariant:** `list_id` cannot be reassigned or modified once a campaign is created. Editing a campaign permits updates only to `name` and `campaign_date`.

### 1.3 `crm4.crm4_members`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Campaign membership record identifier | Primary key |
| `campaign_id` | UUID | NOT NULL | Parent campaign reference | FK to `crm4.crm4_campaigns.id`; ON DELETE CASCADE |
| `contact_id` | UUID | NOT NULL | CRM-1 contact reference | Valid contact UUID; resolved via CRM-1 API |
| `status` | TEXT | NOT NULL | Engagement status | One of `sent`, `opened`, `clicked` (no arbitrary states) |
| `unsubscribed` | BOOLEAN | NOT NULL | Whether contact unsubscribed via or during campaign | Default false; preserved across imports |
| `created_at` | TIMESTAMPTZ | NOT NULL | Record creation timestamp | Defaults to now(); read-only |

**Domain Invariant:** Member status is strictly restricted to `sent`, `opened`, `clicked`. Campaign delivery, email/SMS dispatch, and transport are out of scope in V1 (history recording only).

### 1.4 `crm4.crm4_consents`

| Field | Type | Nullability | Meaning | Constraints |
|---|---|---|---|---|
| `id` | UUID | NOT NULL | Consent record identifier | Primary key |
| `contact_id` | UUID | NOT NULL | Target CRM-1 contact identifier | Unique per contact; indexed |
| `status` | TEXT | NOT NULL | Consent state | Exactly `subscribed` or `unsubscribed` |
| `consent_date` | TIMESTAMPTZ | NOT NULL | Timestamp of consent event | Defaults to now() |
| `source` | TEXT | NOT NULL | Origin/channel of consent assertion | Non-blank string (e.g. form, CSV batch) |
| `created_at` | TIMESTAMPTZ | NOT NULL | Audit creation timestamp | Defaults to now(); read-only |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Audit update timestamp | Defaults to now(); writers refresh on update; read-only |

**Business Rule BR-CRM4-01:** Opt-out / unsubscribe is strictly monotonic. Once a contact is marked `unsubscribed`, neither migration imports nor standard UI actions may revert the status to `subscribed`. Any membership write or consent update verifies this monotonic invariant.

### 1.5 `crm4.crm4_import_batches`

| Field | Type | Nullability | Meaning | Constraints |

### 1.6 `crm4.crm4_import_receipts`

| Field | Type | Nullability | Meaning | Constraints |

| `source_system` | TEXT | NOT NULL | Origin system tag | Non-empty string |

| `idempotency_key` | TEXT | NOT NULL | Row idempotency key | Unique |
| `created_at` | TIMESTAMPTZ | NOT NULL | Receipt timestamp | Default now() |

## 3. Scope Boundaries & Constraints

1. **Campaign History Only:** No outbound email, SMS, SMTP, or delivery queue integrations exist in V1.
2. **Deterministic Opt-Out (BR-CRM4-01):** Opt-out is strictly monotonic. No automatic or fuzzy re-subscription is permitted.
3. **List Immutability:** Campaigns belong to one list throughout their lifecycle; reassignment is rejected.
4. **Member Status Allowlist:** Only `sent`, `opened`, and `clicked` are valid statuses.
5. **Security & RBAC:** All routes require `Capabilities.MODULE_READ`. Unauthenticated sessions are redirected to Hub login with returnUrl preservation.

### 4.3 Field-Level Protection & Masking
- Bank details formatted as `XXXX-XXXX-7890` (preserving only last 4 digits).
- Salary values formatted as `XX,XXX` or `salary hidden`.
- Neutralization of CSV formula injection (`=`, `+`, `-`, `@`, `\t`, `\r` escaped with leading apostrophe `'`).
- Sensitive object redaction and log sanitization preventing credentials, tokens, and raw rows from leaking into logs or audit records.

### 4.4 Append-Only Audit Logging
- Managed by `Crm4AuditService` recording actor, action, timestamp, entity, correlation, outcome, and pre-redacted diffs without plain secrets.
